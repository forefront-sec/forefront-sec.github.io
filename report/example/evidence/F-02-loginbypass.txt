## Rules
1. **Raw response is sacred** — no trimming, no redaction, no commentary inside the RAW section. Commentary lives in VERIFICATION NOTE.
2. **One finding, one file.** Multi-step proofs (e.g., F-04's register→login→read chain) go in one file as numbered COMMAND/RESPONSE pairs, in order.
3. **State-mutating proofs** (PUT/POST/DELETE): note the mutation in the verification note, capture before/after responses, and restore state where safe. If mutation can't be undone, cite the session capture instead and say so.
4. **Disproven hypotheses get files too** (`F-XX-DISPROVEN-*.txt`) — a negative with a root cause is rigidity evidence; auditors and clients both read the appendix.
5. **Timestamps in UTC**, captured-by named. Append-only: corrections are new blocks, never edits.
6. **Never include client secrets in evidence** — mask tokens/keys where they're not the finding itself (e.g., show first 20 chars of a JWT, not the whole signature).
7. Companion transcript: the full session export goes in `02-evidence/session-transcript-<date>.txt` — the per-finding files are the index, the transcript is the raw history.

## Worked example
See `clients/2026-10-juice-shop-lab/02-evidence/F-01-sqli.txt` — the reference implementation of this structure.

## Naming convention
`F-XX-shortname.txt` matching the report's finding IDs exactly. Disproven: `F-XX-DISPROVEN-reason.txt`. Multi-part: `F-XX-part1-*.txt`, `F-XX-part2-*.txt`.
