Active lanes

Repository & dependency scanning

What it is: read-only analysis of git repositories, built container images, and pull requests — dependency CVEs matched against OSV.dev and GHSA, leaked secrets, Dockerfile and IaC misconfiguration, risky source patterns. Scanned code is never built, installed, or executed — static, manifest, and layer analysis only.

The differentiator is the triage layer: frontier-grade AI — every output human-verified — suppresses false positives with reasons, explains each surviving flag in plain language, ranks by exploitability and exposure, and drafts the fix (a dependency-bump PR or a config patch). A scanner nobody trusts produces noise; a triage layer that shows its work produces evidence.

Status: spec'd, in the lab — it never runs ahead of the pentest work. First surfaces when it ships: a generic container and a GitHub Action.

Smart-contract analysis

What it is: the same engine pointed at on-chain code. Fork at a pinned block into an isolated sandbox, AI audit plus guided fuzzing, every candidate finding validated before it is reported, disclosure to the deployer first — coordinated, embargoed, no exceptions.

Why this lane exists: published research (SCONE-bench, December 2025) showed frontier AI agents exploiting 55.8% of post-knowledge-cutoff smart-contract vulnerabilities in simulation, finding two novel zero-days at roughly $1.22 of compute per contract scanned — with exploit revenue doubling every 1.3 months. The attacker economics arrived first; the defensive method should not be far behind.

Status: parked. No audit service is offered today. The lane opens when a crypto-native client pulls and our coverage fits the risk — not before.
